# VPC Flow Logs Reference

Senrigan loads Amazon VPC Flow Logs from the same S3 copy as CloudTrail and hunts over them on the 🌊 **VPC Flow** agent page and the **VPC Flow Logs Threat Hunting** dashboard.

## Setup

Copy the whole `AWSLogs/` prefix. Each file is routed by its AWS object name; digests, AWS Config, ELB logs and other files are skipped and counted in the ingest summary.

```bash
aws s3 sync s3://<your-bucket>/AWSLogs/ docker/logs/AWSLogs/
make ingest
make up
```

## What is ingested

- Plain-text flow logs (`.log.gz`), default or custom format, in the default, hourly or Hive-compatible S3 layout. Every field AWS documents is kept, and fields added by AWS later are preserved.
- Parquet flow logs are not supported: they are skipped and counted.
- With GeoLite2 in `docker/data/geoip/`, every address gets country, city and ASN; `ingester enrich` fills them in later.

## Reading flow evidence

- A row is one flow observed on one interface in one aggregation window — never a connection. Intra-VPC traffic is observed twice.
- `ACCEPT` means a security group or NACL allowed the packets, not that a session was established.
- Local and remote endpoints are definitive only when the record carries `flow-direction` (`direction_source = 'record'`).
- Records rejected by Block Public Access carry no bytes, and `traffic_path = 2` means internet gateway *or* gateway endpoint.
- Traffic to the Amazon DNS resolver, instance metadata, Time Sync and DHCP is never logged.
