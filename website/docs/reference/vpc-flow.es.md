# Referencia de VPC Flow Logs

Senrigan carga los Amazon VPC Flow Logs desde la misma copia de S3 que CloudTrail y permite cazar sobre ellos en la página de agente 🌊 **VPC Flow** y en el panel **VPC Flow Logs Threat Hunting**.

## Configuración

Copia todo el prefijo `AWSLogs/`. Cada archivo se clasifica por su nombre de objeto de AWS; los digests, AWS Config, los registros de ELB y otros archivos se omiten y se cuentan en el resumen de ingesta.

```bash
aws s3 sync s3://<your-bucket>/AWSLogs/ docker/logs/AWSLogs/
make ingest
make up
```

## Qué se ingiere

- Flow logs en texto plano (`.log.gz`), en formato predeterminado o personalizado, con la disposición de S3 predeterminada, por horas o compatible con Hive. Se conservan todos los campos que documenta AWS, también los que añada más adelante.
- Los flow logs en Parquet no son compatibles: se omiten y se cuentan.
- Con GeoLite2 en `docker/data/geoip/`, cada dirección obtiene país, ciudad y ASN; `ingester enrich` también puede añadirlos después.

## Cómo leer la evidencia de flujo

- Una fila es un flujo observado en una interfaz durante una ventana de agregación, nunca una conexión. El tráfico interno de la VPC se observa dos veces.
- `ACCEPT` significa que un grupo de seguridad o una NACL permitió los paquetes, no que se estableciera una sesión.
- Los extremos local y remoto solo son definitivos cuando el registro incluye `flow-direction` (`direction_source = 'record'`).
- Los registros rechazados por Block Public Access no tienen bytes, y `traffic_path = 2` significa puerta de enlace de Internet *o* punto de enlace de puerta de enlace.
- El tráfico hacia el resolvedor DNS de Amazon, los metadatos de instancia, Time Sync y DHCP nunca se registra.
